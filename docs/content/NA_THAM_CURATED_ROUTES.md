# เส้นทางนำร่องหน้าถ้ำ: ข้อมูลและแนวทางเผยแพร่

ตรวจค้นแหล่งข้อมูล: 29 กันยายน 2569 (2026-09-29)

## ขอบเขตและการตัดสินใจ

รายการที่ยืนยันใน migration `20260919001000_scope_na_tham_pilot_catalog.sql` มี **11 แห่ง** ไม่ใช่ 12 แห่ง การนับนี้อ้างอิงรายการใน repository ไม่ใช่ผลตรวจฐานข้อมูล production วันนี้ ไม่สร้างสถานที่ลำดับที่ 12 ขึ้นเอง

ใช้ 3 เส้นทางคัดสรรสั้นจากสถานที่เดิม ทุกเส้นทางเป็นข้อเสนอเชิงบรรณาธิการ ไม่ใช่ทริปที่หน่วยงานรับรอง ไม่ใช่เส้นทางที่คำนวณว่าเร็วที่สุด และยังต้องยืนยันภาคสนามก่อนเผยแพร่ `day_number = 1` หมายถึงจัดจุดแวะไว้ในวันเดียวกัน ไม่ใช่หลักฐานว่าเดินทางเสร็จได้ภายในเวลาที่กำหนด

| เส้นทาง | จุดแวะตามลำดับเสนอ | เงื่อนไขก่อนเผยแพร่ |
| --- | --- | --- |
| หน้าถ้ำ: ศรัทธาและมรดกวัดคูหาภิมุข | วัดคูหาภิมุข → พ่อท่านเจ้าเขา → ถ้ำพระนอน → พิพิธภัณฑ์ศรีวิชัย | ตรวจเส้นทางเดิน บันได จุดจอดรถ และการเปิดพิพิธภัณฑ์ |
| หน้าถ้ำ: จากศิลปะถ้ำสู่ผืนผ้าสีมายา | พิพิธภัณฑ์ศรีวิชัย → ถ้ำศิลป์ → ชุมชนสีมายา บ้านหน้าถ้ำ | ยืนยันการเข้าถ้ำและนัดหมายชุมชน กิจกรรมไม่รับประกันว่ามีทุกวัน |
| หน้าถ้ำ: เรียนรู้เขากำปั่นกับผู้ดูแลท้องถิ่น | วัดคูหาภิมุข → เพิงผาเขากำปั่น → ถ้ำสำเภาทอง | ผู้ดูแลยืนยันจุดนัดพบ ทางเข้า สภาพพื้นที่และผู้พาเข้าชมก่อน ห้ามสื่อว่าเป็นทริปเข้าถ้ำเอง |

ถ้ำมืด ถ้ำนางมณโฑ และถ้ำเสือยังอยู่ในรายการนำร่อง แต่ไม่ใส่ในชุดเส้นทางเริ่มต้นจนกว่าจะยืนยันการเข้าถึง ไม่ลบหรือปิดสถานที่เหล่านี้ด้วย seed นี้ ไม่บังคับทุกเส้นทางแวะครบทุกแห่ง และไม่เพิ่มร้านอาหารหรือที่พักนอกชุดข้อมูลจริง

## วิเคราะห์ข้อเสนอ GPT

รับแนวคิดภาพปกจริง ลำดับจุดแวะชัด แผนที่ประกอบ การตรวจความพร้อมก่อนเผยแพร่ และการลดงานกรอกซ้ำ แต่ไม่รับตัวอย่างเบตง/หลายวันหรือการเพิ่มระบบใหญ่เพียงเพราะมีตัวอย่างในเอกสาร

โค้ดปัจจุบันมี draft, ตัวเลือกสถานที่, จุดแวะแยกวัน, หมายเหตุ, รูปปก, readiness, แผนที่โหลดเมื่อกด และลิงก์ Google Maps แบ่งช่วงอยู่แล้ว จึงปรับเฉพาะข้อบกพร่องที่ตรวจพบ ไม่สร้างระบบเส้นทางใหม่ซ้ำ

### UX ฝั่งสาธารณะ

- หน้า `/routes`: ชุดเล็ก 3 เส้นทางที่เปรียบเทียบง่าย ใช้ typography สี ภาพและระยะห่างจากหน้า home ปัจจุบัน ไม่มีตัวกรองที่ทำให้หน้าว่างเปล่าดูซับซ้อนเมื่อมีเพียง 3 รายการ
- รายละเอียด: บทนำสั้น → จุดแวะเรียงลำดับและหมายเหตุ → แผนที่พร้อมหมายเลขเดียวกัน → เปิด Google Maps ไม่แสดงระยะทางหรือเวลาที่ไม่ได้คำนวณจริง
- มือถือให้เนื้อหาจุดแวะมาก่อน ไม่ให้แผนที่กินทั้งหน้าหรือปุ่ม sticky บังเนื้อหา หน้าแผนที่ต้องมีทางไปอ่านรายละเอียดแม้โหลด tile ไม่สำเร็จ
- ไม่มีรูปให้แสดงสถานะที่ตรงจริง ผู้ดูแลเพิ่มปกผ่าน CMS ไม่ hotlink รูปจากเว็บวิจัย และไม่ใส่ภาพสถานที่อื่นแทน

### UX ฝั่งผู้ดูแล

- สร้างร่าง → เลือกสถานที่เดิม → เรียงจุดและใส่หมายเหตุเฉพาะเส้นทาง → เลือกปก → ตรวจและเผยแพร่
- ไม่คัดลอกชื่อ ที่อยู่ พิกัด รูป หรือรายละเอียดสถานที่มาเป็นช่องกรอกใหม่ในเส้นทาง
- คงปุ่มเลื่อนลำดับที่ใช้คีย์บอร์ดได้ ต่อให้เพิ่มลากวางในอนาคต ไม่ใช้ drag-only
- แสดงปัญหาจริงเป็นรายการ เช่น ไม่มีปก จุดไม่พร้อมเผยแพร่ ยังมีการแก้ไขไม่บันทึก ไม่สร้างเปอร์เซ็นต์ความพร้อมตามอำเภอใจ
- ความพร้อมทางเทคนิคไม่เท่ากับความปลอดภัยภาคสนาม ผู้ดูแลต้องยืนยันการเข้าถึงด้วย

## แผนที่และการนำทาง

ใช้ Leaflet เดิมสำหรับแผนที่ประกอบ และ Google Maps URL สำหรับเปิดแอป/เว็บภายนอก ผู้ใช้เลือกวิธีเดินทางตามสภาพจริง ไม่ขอ GPS ในเว็บเพื่อเปิดลิงก์ ขีดจำกัด waypoints บน mobile browser คือ 3 จุดระหว่างทาง จึงคงการแบ่งลิงก์ไม่เกิน 5 จุดรวมต้นทางและปลายทาง มีจุดต่อเนื่องซ้อนกันระหว่างช่วง

พิกัดอ้างอิงที่ค้นยืนยันได้:

| แหล่ง | Latitude | Longitude | ประเภทหลักฐาน |
| --- | --- | --- | --- |
| ภูเขาวัดหน้าถ้ำ/วัดคูหาภิมุข | 6.528737 | 101.224914 | ตำแหน่งแหล่งโบราณคดี SAC ไม่ใช่จุดจอดรถที่ยืนยัน |
| ถ้ำศิลป์ | 6.522165 | 101.233363 | ตำแหน่งแหล่งโบราณคดี SAC ไม่ใช่จุดเข้าถึงโดยรถที่ยืนยัน |

**ไม่เขียนทับพิกัด CMS ด้วยสองค่านี้อัตโนมัติ และไม่ใช้พิกัดวัดเดียวกันแทนทุกถ้ำ** อีก 9 จุดต้องเทียบข้อมูล CMS กับจุดจริง/ผู้ดูแลก่อนใช้นำทาง ไฟล์ preflight สร้างลิงก์เปิดหมุดที่บันทึกไว้เพื่อให้ตรวจทีละจุด รวมทั้งเทียบสองพิกัดอ้างอิงข้างต้น

ลิงก์ [360 หน้าถ้ำของ มรย.](https://yala360.yru.ac.th/Natham/) คงเป็นเว็บไซต์ภายนอก ไม่ใช้เป็นหลักฐานว่าเส้นทางเดินปลอดภัยหรือเปิดให้เข้า ปัจจุบันเครื่องมือค้นเว็บดึงหน้าไม่ได้ จึงไม่ได้อ้างว่าได้ตรวจข้อมูลภายในแล้ว

## SQL ที่ส่งมอบ

1. รัน `supabase/seed/na_tham_routes_preflight.sql`: อ่านอย่างเดียว แสดงครบ 11 slugs สถานะ พิกัด และลิงก์ตรวจหมุด
2. รัน **ทั้งไฟล์** `supabase/seed/na_tham_curated_routes.sql`: transaction เดียว สร้าง 3 ร่าง/10 จุดแวะ ตรวจสถานที่ active + published + Yala สำหรับเส้นทางใหม่ ถ้าไม่พร้อมให้หยุดทั้งหมด
3. หากเกิด error ใน transaction ให้ `ROLLBACK;` ก่อนรันใหม่ แก้สถานที่ต้นทางผ่าน CMS ไม่ลบเงื่อนไขตรวจข้อมูล
4. ไป `/admin/routes` เพิ่มรูปปก ตรวจหมายเหตุ ลำดับ จุดเข้าเยี่ยมชมและแผนที่ แล้วเผยแพร่ผ่านปุ่มของระบบ เพื่อใช้ permission/readiness/audit/cache revalidation เดิม

ไม่มี schema migration ใหม่ ไม่มีข้อมูลผู้ใช้/สำรวจ/เช็กอินสมมติ ไม่มีการแตะสถิติ และไม่ได้รัน SQL นี้บน production แทนผู้ใช้

ตรวจ SQL ด้วย `node scripts/verify-na-tham-route-seed.mjs`: ผ่าน 10 กรณีบน PostgreSQL/WASM (PGlite) ฐานข้อมูลแยกในหน่วยความจำ โดยใช้ table definitions ของ repository รวม unique constraints และการถอด `cover_image_path` ตาม schema ปัจจุบัน ครอบคลุม insert, rerun, รักษา CMS edits, สถานที่หาย/ปิด/ไม่เผยแพร่/ผิดจังหวัด, rollback เมื่อชื่อชน และรายงานพิกัด ไม่ใช่การยืนยัน RLS/auth หรือ Supabase production ทั้งระบบ runtime QA ติดตั้งเฉพาะ `.tmp-tests/route-seed-runtime` ไม่เพิ่ม dependency ของแอป

รัน seed ซ้ำจะข้าม slug ที่มีอยู่ทั้งรายการ **ไม่แก้ชื่อ ปก จุดแวะ หมายเหตุ หรือสถานะ** แม้ผู้ดูแลจะปรับแล้วก็ตาม หากลบจุดแวะใน CMS ตั้งใจไว้ seed จะไม่เติมกลับ เส้นทางชื่ออังกฤษชนกับรายการอื่นจะ fail แทนการรวมผิดรายการ

การย้อนกลับให้เก็บเป็นร่าง/เก็บถาวรผ่าน CMS ไม่ลบสถานที่หรือข้อมูลท่องเที่ยว ไม่ใช้ DELETE แบบ cascade กับข้อมูลจริง

## เกณฑ์อนุมัติข้อมูลจริง

- ผู้ประสานชุมชนยืนยันลำดับทริป จุดนัดพบ ทางเข้า ข้อจำกัดบันได/ถ้ำ และวิธีติดต่อที่อนุญาตให้เผยแพร่
- พิกัดแต่ละจุดตรงสถานที่ ไม่ใช่พิกัดจังหวัดหรือศูนย์กลางภูเขาที่สื่อเป็นที่จอดรถ
- ตรวจ Google Maps บน iPhone และ Android จริง เส้นทางรถต้องไม่อ้างว่าเข้าถึงตัวถ้ำได้
- ผู้ดูแลเพิ่มภาพปกที่มีสิทธิ์ใช้และตรวจหลัง refresh
- ทดสอบเผยแพร่/ยกเลิกเผยแพร่และ public cache ด้วยข้อมูลจริงหลังรัน seed
