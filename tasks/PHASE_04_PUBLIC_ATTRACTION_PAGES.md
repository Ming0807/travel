# PHASE_04_PUBLIC_ATTRACTION_PAGES.md

## Status

Planned

## Objective

Create public attraction and tourism portal pages that support discovery, SEO, project credibility, and trust for Yala, Pattani, and Narathiwat.

Public pages are not the main data collection entry point. QR check-in remains the main field data collection entry point.

## Product Strategy

The public website should support:

- attraction discovery
- travel stories and SEO content
- suggested routes
- 360 media
- project credibility
- privacy/trust explanation
- certificate/passport explanation
- dashboard value preview using aggregate examples only

The latest homepage direction is defined in:

```text
docs/frontend/HOMEPAGE_UI_STRATEGY.md
docs/frontend/AI_DESIGN_BRIEF.md
```

## Scope

MVP / Optional MVP:

- homepage or discovery landing page
- attraction list
- attraction detail page
- province filter chips
- search
- certificate/passport explanation cards
- privacy/trust section

Phase 2:

- travel stories
- suggested routes
- richer masonry discovery feed
- 360 media sections
- dashboard preview section

Out of MVP:

- long booking flow
- native app requirement
- public tourist data pages
- automatic social posting

## Acceptance Criteria

- Public pages are mobile-first and premium/app-like.
- Homepage follows the dark emerald, mist, white card, warm gold, and subtle coral direction.
- Public pages do not expose private tourist data or storage paths.
- Public pages explain that certificate creation normally starts from QR at the attraction/photo spot.
- Public pages support Thai and English content structure.
- Public pages do not require login.
